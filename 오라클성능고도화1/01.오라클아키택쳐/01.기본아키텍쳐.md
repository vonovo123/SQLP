사용자가 입력하는 내용을 파일에 직접 I/O 한다면 작은 파일을 편집하더라도 속도가 늦다. 메모리 케시의 도움이 필요하다.

이에 오라클은 데이터베이스와 이를 액세스하는 프로세스 사이에 SGA라고 하는 메모리 캐시 영역을 둔다.

메모리 캐시는 전기적 신호이므로 속도가 빠르다.

데이터베이스의 특징은 다수의 프로세스가 동시에 데이터를 엑세스한다는 점이다.

이로 인해 사용자 데이터를 보호하는 LOCK 은 물론 공유 메모리 영역인 SGA 상에 위치한 데이터 구조에 대한 액세스를 직렬화하기위한 LOCK 메커니즘도 필요해진다.

오라클은 블록 단위로 읽고, 저장할 때도 변경이 발생한 블록만 찾아 블록 단위로 저장한다.

캐시와 데이터파일간의 동기화를 위해 백그라운드에서 DBWR와 CKPT 프로세스가 작동한다.

오라클에서 디스크에 저장된 데이터 집합을 '데이터베이스'라고 부른다. 그리고 SGA 공유 메모리 영역과 이를 액세스하는 프로세스 집합을 합쳐 '인스턴스'라고 부른다.

프로세스 집합은 다시 서버 프로세스와 백그라운드 프로세스 집합으로 나뉜다.

서브 프로세스는 전면에서 사용자가 던지는 명령어를 처리하고, 벡그라운드 프로세스는 주어진 역할을 수행한다.

사용자가 오라클에 접속하면 각각의 사용자(클라이언트) 를 위한 전용 서버 프로세스가 떠서 필요한 서비스를 제공한다.

SQL을 파싱하고 최적화를 수행하며, 커서를 열어 SQL을 실행하면서 블록을 읽고, 읽은 데이터를 정렬해 클라이언트가 요청한 결과집합을 만들어 네트워크로 전송하는 작업을 서버프로세스가 처리한다.

데이터파일로부터 DB 버퍼캐시로 블록을 적재하는 일, DIRTY BLOCK을 캐시에서 밀어내어 FREE 블록을 확보하는 일, REDO 로그 버퍼를 비우는 일 등 서버프로세스 단독으로 처리할 수 없는 일을 만나면 백그라운드 프로세스에 신호를 보내 처리를 요청한다.

#### sqlplus를 통해 ORACLE에 접속하면 생기는 일

1. 오라클에 접속하면 연결요청을 받은 오라클 listner 가 서버프로세스에 연결요청을 상속한다.
2. 연결요청을 상속받은 서버프로세스는 인스턴스별 메모리인 pga를 생성한다.
3. 메모리가 생성되면 서브프로세스는 사용자에게 응답을 전송한다.

---

리스너에 연결요청을 하는 순간 하나의 서버프로세스를 띠우고 pga를 할당한다. 이는 비용이 매우 큰 작업으로 오라클에 접속하는 애플리케이션을 구축할때는 항상 커넥션 풀 기능을 이용해야한다.

한번 커낵션을 맺으면 작업을 완료하더라도 이를 해제하지않고 애플리케이션 서버에서 POOLING하고 있다가 반복해서 재사용한다.

이와 같은 재사용성은 데이터베이스 성능튜닝의 핵심 원리이다.

기본구성으로 오라클을 설칳라면 하나의 데이터베이스에 접근하는 하나의 인스턴스가 생성되지만 RAC환경에서는 하나의 데이터베이스를 액세스하는 다중 인스턴스로 구성된다.

뿐만아니라 RAC 모델은 데이터파일만을 공유하는 방식을 넘어 공유 캐시방식을 지원한다.

글로벌 캐시 개념을 사용해 로컬 캐시에 없는 데이터 블록을 이웃 노드에서 전송받아 서비스할 수 있다. 각 인스턴스를 고속의 전용 네트워크로 연결하기 때문에 가능하다.

심지어 다른 인스턴스로부터 갱신하고 아직 커밋하지 않은 ACTIVE 상태의 블록까지도 디스크를 경유하지 않고 DIRTY 버퍼 상태에서 네트워크를 통해 주고받으며 갱신을 수행할 수 있다.

RAC 이전 환경에서는 타 노드에 캐싱된 DIRTY 버퍼를 읽고자 할 때 디스크로의 쓰기 작업이 선행되야했고, 디스크를 거치는 과정을 PING이라고 불렀다.

여러 개의 인스턴스가 하나의 데이터베이스를 액세스 하는 것은 가능하지만, 어떤 환경에서도 하나의 인스턴스가 여러 개의 데이터베이스를 액세스할 수는 없다.

SQL을 튜닝할때 가장많이 사용하는 툴킷은 SQL 트레이스다.
