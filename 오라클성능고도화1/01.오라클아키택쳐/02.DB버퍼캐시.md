사용자가 입력한 데이터를 데이터파일에 저장하고 이를 다시 읽는 과정에서 SGA 구성요소 중 하나인 DB 버퍼 캐시를 거친다.

## 블록단위 I/O

메모리 버퍼 캐시에서 버퍼 블록을 엑세스할 때, 데이터파일에 저장된 데이터 블록을 DB버퍼 캐시로 적재하거나 캐시에서 변경된 블록을 다시 데이터파일에 저장할때도 블록단위로 처리한다.

데이터파일에서 버퍼 캐시로 블록을 적재할 때, 인덱스를 경유하는 테이블엑세스는 블록 단위로 읽어들이지만 TABLE Full Scan시 에는 성능 향상을 위해 한 번에 여러 블록을 읽어들인다.

DBWR가 버퍼 캐시로부터 변경된 블록을 주기적으로 데이터 파일에 기록하는 동기화 작업을 수행할 때도 성능을 위해 한 번에 여러 블럭을 처리한다.

블록 단위로 읽는다는 것은, 하나의 레코드에서 하나의 컬럼만을 읽고자 하더라도 레코드가 속한 블록 전체를 읽게 됨을 의미한다.

옵티마이저가 인덱스를 이용해 테이블을 액세스할지 아니면 FULL TABLE SCAN 할지를 결정할때 가장 중요한 판단기준은 읽어야할 레코드의 수가 아닌 블록의 개수이다.

## DB 버퍼 캐시 구조

DB 버퍼 캐시는 해시 테이블 구조다.

키 값을 해시 값으로 변환해서 해시 버킷을 찾아가는 속도가 워낙 빨라서 각 버킷에 기록되는 인테르 개수를 일정 수준으로 유지할 수만 있다면 해싱에 의한 검색속도가 가장 빠르다.

데이터 블록을 해싱하기 위해 사용되는 키 값은 데이터 블록 주소(DBA, DATA BLOCK ADDRESS) 이다.

해시 함수에 데이터 블록 주소를 입력해 리턴받은 해시 값이 '같은' 블록을 해시 버킷에 링크드 리스트 구조로 연결한다.

해싱한 주소로 연결리스트를 찾으면 바로 읽고, 찾지 못하면 디스크에서 읽어 해시 체인에 연결한 후 읽어온다.

버퍼 헤더만 해시 체인에 연결되고 버퍼 헤더에 있는 포인터를 이용해 실제 버퍼블록을 찾는다.

## 캐시 버퍼 체인

해시 체인은 래치에 의해 보호된다.

DB 버퍼 캐시는 공유 메모리 연역인 SGA 내에 존재하므로 여러 프로세스에 의한 동시 액세스가 발생할 가능성이 크다.

따라서, 동일 리소스에 대한 액세스 직렬화가 필요하고, 이를 위해 구현된 일종의 LOCK 메커니즘을 래치라고 부른다.

래치를 획득한 프로세스만이 자료구조로의 진입이 혀옹된다.

두 개 이상의 프로세스가 같은 해시 체인으로 진입해 새로운 버퍼 블록을 연결하고 해제하는 작업을 동시에 진행하면 문제가 발생할 수 있다.

이를 방지하기 위해 사용하는 것이 CACHE BUFFERS CHAINS 래치이다.

하나의 CACHE BUFFERS CHAINS 래치가 여러 개의 해시 체인을 동시에 관리한다. 하나의 래치가 관리하는 해시 체인의 수는 버퍼 캐시의 크기와 버전에 따라 달라진다.

오라클 9I 부터 읽기전용 작업의 경우 CACHE BUFFERS CHAINS 래치를 SHARED 모드로 획득할 수 있다. 읽기전용 작업은 해시 체인을 스캔하면서 필요한 블록을 찾는 작업을 말한다.

SELECT 문장은 SHARED 모드 래치를 사용하는 것과 관계없이, 여전히 CACHE BUFFERS CHAINS 래치 경합이 발생한다.

래치는 데이터 자체를 보호하는 것이 아니라 SGA에 공유돼 있는 자료구조를 보호하는 것이며, 그중 CACHE BUFFERS CHAINS 래치는 버퍼 캐시에 연결된 체인구조를 보호한다.

## 캐시 버퍼 LRU 체인

버퍼 헤더는 해시 체인 뿐 아니라 LRU 체인에 의해서도 연결돼 있다.

메모리는 유한한 자원이기 때문에 사용빈도가 높은 데이터 블록 위주로 구성될 수 있도록 LRU 알고리즘으로 관리된다.

메모리 내의 FREE가 필요해질 때마다 액세스 빈도가 낮은 데이터 블록을 우선하여 밀어내 자주 액세스되는 블록들이 캐시에 오래 남도록 관리한다.

\- Drity List : 캐시 내에서 변경됐지만, 아직 디스크에 기록되지 않은 Dirty 버퍼 블록을 관리하는 리스트,

\- LRU LIST : 아직 Dirty List로 옮겨지지 않은 나머지 버퍼블록을 관리

모든 버퍼블록은 이 둘중 하나에 속하지만 읽기 또는 쓰기 작업을 위해 액세스 되는 동안에는 리스트에서 잠시 풀려나왔다가 다시 원래의 리스트로 연결되거나, 최초 변경이 발생했을때는 DIRTY LIST로 옮겨간다.

LRU 리스트를 보호하기 위해 사용하는 래치를 CACHE BUFFERS LRU CHAIN 이라고한다.

### 버퍼 상태

모든 캐시 버퍼는 Free ,Dirty, Pinned 세 가지중 하나의 상태에 놓인다.

Free 버퍼는 인스턴스 기동 후에 아직 데이터가 읽히지 않아 비어있는상태이거나 데이터가 담겼지만 데이터 파일과 동기화돼 언제든 덮어써도 무방한 상태이다.

테이터 파일로부터 새로운 데이터 블록을 로딩하려면 먼저 FREE 버퍼를 확보해야한다. FREE 상태에서 버퍼에 변경이 발생하면 그순간 DIRTY 버퍼로 상태가 바뀐다.

Dirty 버퍼는 버퍼에 캐시된 이후 변경이 발생햇지만, 아직 디스크에 기록되지 않아 데이터 파일 블록과 동기화가 필요한 버퍼 블록을 말한다. 재사용을 위해서는 디스크에 먼저 기록되야한다.

Pinned 버퍼 : 읽기 또는 쓰기 작업을 위해 현재 액세스되고 있는 버퍼 블록을 말한다.
