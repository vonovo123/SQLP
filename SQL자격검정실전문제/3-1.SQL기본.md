26. DELETE, TRUNCATE, DROP 명령어에 대한 비교설명

a.특정 테이블에 대해 WHERE 조건절이 없는 DELETE 명령을 수행하면 DROP TABLE 명령을 수행했을 때와 같은 결과를 얻는다.
=> DELETE는 데이터만 삭제하지만 DROP 명령어는 테이블 정의 자체를 완전히 삭제한다.
b.DROP 명령어는 테이블 정의 자체를 삭제하고, TRUNCATE 명령어는 테이블을 초기상태로 만든다.
c.TRUNCATE 명령어는 UNDO를 위한 데이터를 생성하지 않기 때문에, 동일 데이터량 삭제시 DELETE보다 빠르다.
=> AUTO COMMIT 되므로 복구를 위한 UNDO를 만들필요없음
d.DROP은 AUTO COMMIT 되고, DELETE와 TRUNCATE는 사용자 Commit으로 수행된다.
=> TRUNCATE는 AUTO COMMIT 된다.

b.일관성 : 트랜잭션이 성공적으로 수행되면 그 트랜잭션을 갱신한 데이터베이스의 내용은 영구적으로 저장된다.
=> 지속성에 대한 설명이다.
c.고립성 : 트랜잭션이 실행되는 도중에 다른 트랜잭션의 영향을 받아 잘못된 결과를 만들어서는 안된다.
d.지속성 : 트랜잭션이 실행 되기 전의 데이터베이스 내용이 잘못돼있지 않다면 실행후에도 잘못된 내용이 있어서는 안된다.
=> 일관성에 대한 설명이다.

28. 트랜잭션에 대한 격리성이 낮은 경우 발생할 수 있는 문제점으로 부적절한 것

a. Dirty Read : 다른 트랜잭션에 의해 소정되었고 이미 커밋된 데이터를 읽는것을 말함
=> 다른 트랜잭션에 의해 수정됏찌만 아직 커밋되지 않은 데이터를 읽는 것을 말함
b. Non-Repeatable REad : 한 트랜잭션 내에서 같은 쿼리를 두 번 수행했는데, 그 사이에 다른 트랜잭션이 값을 수정/삭제 하는 바람에 두 쿼리의 결과가 다른경우를 말함
c. Phantom REad : 한 트랜잭션 내에서 같은 쿼리를 두 번 수행했는데 첫번째 쿼리에서 없던 유령 레코드가 두번째 쿼리에서 나타나는 현상을 말함
d. isolation : 트랜잭션이 실해회는 도중 다른 트랜잭션의 영향을 받아 잘못된 결과를 만들어내서는 안됨
=> 트랜잭션의 4가지 특성으로 문제점이 아닌 목표

29. 벤더별 DDL TRANSACTION 범위

아래 SQL 수행후 최종 VAL 값이 ORACLE에서는 200, SQL Server에서는 100이 된다.
(Auto Commit은 False 상태이다.)

```sql
-- TABLE A
-- ID   val
-- 001  100
-- 002  200

UPDATE A SET VAL = 200 WHERE ID = '001';
CREATE TABLE B(ID CHAR(3) PRIMARY KEY);
ROLLBACK;
```

a. ORACLE에서느 CREATE TABLE 문장을 수행한 후, 묵시적으로 COMMIT이 수행되어 VAL 값음 200이 됐다.
=> ORACLE에서는 DDL 문장 수행 후 자동으로 COMMIT을 수행한다.
b. SQL Server에서는 Rollback 문장에 의해 UPDATE가 취소되어 Val 값은 100이 된다.
=> SQL SERVER에서는 DDL 문장 수행 후 자동으로 Commit을 수행하지않는다.
c. Oracle에서는 CREATE TABLE 문장 수행에 의해 val 값은 200이 됐지만, Rollback 실행으로 인하여 최종적으로 B테이블은 생성되지 않았다.
=> Oracle에서는 DDL 문장 수행 후 내부적으로 트랜잭션을 종료시키므로 B 테이블은 생성된다.
d. SQL Server에서는 Rollback 실행으로인해 UPDATE가 취소됐으며, 최종적으로 B테이블은 생성되지 않았다.
=> SQL SERVER에서 CREATE TABLE 문장도 TRANSACTION의 범주에 포함된다. 그러므로 ROLLBACK 문장에 의해 최종적으로 B테이블은 생성되지 않는다.
