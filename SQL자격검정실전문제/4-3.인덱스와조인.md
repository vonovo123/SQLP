c. SQL2는 v\_판매시작일자 변수에 오랜과거일자를 입력할때보다 최근 일자를 입력할때 비효율이 적다.
=> 최근일자를 입력하면 판매시작일자 조건을 만족하는 상품 건수가 적어진다.
서브쿼리 A의 조건에 해당하는 많은 일별매출 데이터를 읽고 groupby groupby 했는데, 상품 테이블과 조인하는 과정에서 필터링되는 데이터가 많아진다.
이에 비효율적이다.
d.Query Transformer는 쿼리변환을 수행하여 SQL1에 대해 SQL2와 유사한 실행계획을 수립하기도 한다.

61. 선분이력 조인 조건절

```sql
-- 두 변경이력 테이블에 있는 시작일자, 장료일자는 선분이력으로 관리된다.
-- 시작일자에는 이력 레코드 생성일자가 입력되고, 종료일자에는 최초 '99991231' 로 입력되있다가 다음 번 새 이력 레코드가 생성되는 순간
-- 바로 전 일자로 갱신된다.
-- 이름이 홍길동인 고객의 1998.5.29 일자 고객등급과 전화번호를 조회하는 쿼리를 구하시오

-- 고객             -- 고객등급변경이력   -- 전화번호변경이력
-- # 고객번호        -- #변경순번        -- 변경순번
-- 고객명            -- 고객등급         -- 전화번호
-- 고객등급          -- 시작일자          -- 시작일자
-- 전화번호          -- 종료일자          -- 종료일자
-- 거주지역
-- 주소

-- 고객_PK : 고객번호
-- 고객_X01 : 고객명
-- 고객등급변경이력_PK : 고객번호 + 변경순번
-- 고객등급변경이력_X01 : 고객번호  + 시작일자 + 종료일자
-- 고객전화번호변경이력_PK : 고객번호 + 변경순번
-- 고객전화번호변경이력_X01 : 고객번호 + 종료일자 + 시작일자

select
from 고객 C, 고객등급변경이력 C1, 전화번호변경이력 C2
where c.고객명 = 홍길동
and c1.고객번호 = c2.고객번호
and c2.고객번호 = c.고객번호
and '19980529' >= c1.시작일자 and  '19980529' <= C1.종료일자
and '19980529' >= c2.시작일자 and  '19980529' <= C2.종료일자
```

62. 로컬 파티션 인덱스

a. 테이블 파티션과 1:1 대응관계
b. 테이블 파티션 ADD/DROP/SPLIT/EXCHANGE 작업시, 인덱스 파티션도 자동괸리
c. LOCAL 파티션 인덱스의 경우, 인덱스 파티션키가 인덱스 선두 컬럼에 위치해야함.
=> 인덱스 파티션 키가 인덱스 선두 컬럼에 위치해야한다 (PREFIXED)는 제약은 global 파티션 인덱스에 해당한다.
로컬 파티션 인덱스에 경우 prefixed, non-prefixed 모두 가능하다.
d. 테이블 파티션 키가 SQL 조건절에 없을 때, 인덱스 사용 시 비효율 발생
=> 로컬이든 글로벌이든 인덱스 파티션 키가 조건절에 없으면 인덱스 사용 시 비효율이 발생한다.
local 파티션인덱스의 경우 자동으로 테이블 파티션 키로 인덱스 파티션키가 지정된다.
global 파티션으로 생성한 인덱스의 파티션 키가 테이블 파티션의 키라고해서 local 파티션 인덱스인것은 아니다.
