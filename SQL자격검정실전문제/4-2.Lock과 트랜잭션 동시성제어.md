23. 오라클 PL/SQL로 작성한 프로그램을 MS_SQL SERVER T-SQL 구문으로 변환하려할ㄹ때 for update 구문을 대신하기 위해 사요할 힌트

```sql

update 고객 set 적립포인트 = v_적립포인트 where 고객번호 = 100;
```

c. from 고객 with (READPAST)

24. 특정 lock이 발생하는 SQL

```sql
SELECT A.SESSION_ID, A.LOCK_TYPE, A.MODE_HELD, A.MODE_REQUESTED, A.LOCK_ID1. A.LOCK_ID2

WHERE A.SESSION_ID = B.SID

-- 135        TRANSACTION   EXCLUSIVE   NONE      131017    3098
```

TM LOCK이 EXCLUSIVE 모드이므로 APPEND 모드로 입력한 INSERT 문 실행 후 LOCK 발생현황으로 볼 수 있다.

b. 실행을 성공하면 언제나 일관성 있는 데이터베이스 상태로 변환. 즉, 트랜잭션의 실행결과로 데이터베이스의 상태가 모순되지 않음

=> 격리성
d. 트랜잭션이 일단 실행을 성공하면 그 결과는 영속적으로 저장됨
=> 영속성

29. 트랜잭션 동시성 제어에 대한 설명으로 부적절한 것은.

a. 비관적 동시성 제어는 두 트랜잭션이 같은 데이터를 동시에 수정할것이라고 가정하고 데이터를 읽는 시점에 Lock을 설정하는 방식.

b. 낙관적 동시성제어는 두 트랜잭션이 같은 데이터를 동시에 수정하지 않을 것이라고 가정하고 데이터를 읽는 시점에 Lock을 설정하지 않는 방식을 말한다.

이 방식에선 데이터를 수정하는 시점에, 앞서 읽은 데이터가 다른 트랜잭션에 의해 변경됐는지 반드시 확인해야한다.

c. 트랜잭션 격리성 수준을 Serializable로 상향 조정하면 일반적으로 동시성과 일관성이 같이 높아진다.
=> 일관성은 높아지지만 동시성은 떨어진다.

d. 트랜잭션 격리성 수준을 Serializable로 상향 조정하면 프로그램에서 별도의 동시성 제어를 하지 않아도 DBMS가 트랜잭션 단위 일관성을 보장해준다.

---

- READ UNCOMMITED :

트랜잭션에서 처리중인 아직 커밋되지 않은 데이터를 다른 트랜잭션이 읽는 것을 허용

- READ COMMITTED :

트랜잭션이 커밋되어 확정된 데이터만 다른 트래잭션이 읽도록 허용하여 Dirty REad 방지

- REPEATABLE READ

트랜잭션 내에서 쿼리를 두 번이상 수행했을때 첫 벗째 쿼리에 있떤 레코드가 사라지거나 값이 바뀌는 현상을 방지해준다.

- SERIALIZABLE READ

트랜잭션 내에서 쿼리를 두 번 이상 수행할 때, 첫 번째 쿼리에 있떤 레코드가 사라지거나 값이 바뀌지 않음은 물론 새로운 레코드가 나타나지 않는다.

31.MVCC(다중버전 동시성 제어)의 읽기 일관성 메커니즘에 대한 설명으로 부적절한 것

a. 읽기 일관성을위해 undo 세그먼트에 저장된 Undo 데이터를 활용한다.
b. MVCC 모델은 기본적으로 완벽한 문장 수준 읽기 일관성을 보장한다.
c. MVCC 모델은 기본적으로 완변학 트랜잭션 수준 읽기 읽관성을 보장한다.
=> MVCC모델은 무장수준의 읽기 일관성을 완벽히 보장하지만, 트랜잭션 수준의 읽기 일관성을 유지하기위해선 트랜잭션 격리성 수준을 Serializable Read 이상으로 격상해야한다.
d. 트랜잭션 수준 읽기 일관성이란, 트랜잭션이 시작된 시점을 기준으로 일관성 있게 데이터를 읽어들이는 것을 맗나다.
